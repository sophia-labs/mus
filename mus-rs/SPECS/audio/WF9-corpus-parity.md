# WF9 — corpus render parity (`mus-rs/tools/parity_render.py` + tests)

The leg's gate: render every corpus score through BOTH implementations and
measure. The report is the artifact — divergence is documented, never
hidden.

1. **`mus-rs/tools/parity_render.py`** — for each score in `aigua/*.mus`
   (all 13; `bolero.mus` is the long pole — include it, and if wall-clock
   forces a skip, the report must say so explicitly; no silent caps):
   - Python render: import `mus_audio`, `render(score, tmp/py.wav)`
     (use the repo `.venv` python).
   - Rust render: `cargo run -p mus-cli --release -- render <score> -o
     tmp/rs.wav` (build once, then invoke the binary directly).
   - Compare decoded samples (soundfile): exact length match; `max_abs`;
     `rel_rms` (joint over channels); per-channel RMS delta in dB; plus
     receipt comparison (event counts, sidechain hits, bad tokens) —
     receipts must match exactly.
   - Emit `mus-rs/parity/parity-report.json`
     (`mus.audio.parity-report.v1`): per-score `{score, n_samples_{py,rs},
     max_abs, rel_rms, receipt_match, transforms_used, verdict}` plus a
     summary block with the worst offenders.
2. **Bounds** (initial policy; measured values recorded either way):
   scores whose transform set avoids the vocode family (no `mode=vocoder`,
   no `glow`, no `gest=` with pitch shift, no `str`) must meet `rel_rms ≤
   1e-3`; vocode-touching scores `rel_rms ≤ 3e-2` **provisional** — record
   actuals; if a score exceeds its bound the report marks it `diverged`
   and the run exits non-zero, but still writes the full report first.
   Determine each score's transform set by grepping its params — record it
   in the report (`transforms_used`).
3. **Rust-side fast subset**: an integration test in `mus-cli/tests/`
   that renders `smoke.mus` and a second, self-contained fixture via the
   Rust engine and asserts against committed expectation digests
   generated by the tool (`--write-expectations` mode) — so `cargo test`
   catches engine regressions without Python. The second score is
   deliberately NOT `aigua_states.mus`: that score's `# gestures:`/
   `sample=` references resolve to `aigua/v2/sweep-events.json` and
   `aigua/aigua_raw.wav`, both gitignored and absent from a clean
   checkout, which would make the always-on `cargo test` fast subset pass
   only for a developer who had manually copied those two files in. The
   fixture (`mus-cli/tests/fixtures/wf9_offline/`, committed) exercises
   the same two feature families — `gest=` gesture quotation and
   tape-style `off=`/`gate`/`lpf=` sample playback — against its own
   small committed assets, cross-checked against the oracle before being
   frozen (see `parity_render.py`'s `WF9_OFFLINE_FIXTURE`). A dedicated
   test (`clean_checkout_copy_renders_the_fast_subset`) stages only the
   git-tracked fast-subset inputs into an isolated temp directory and
   renders from there, proving the fast subset needs nothing beyond what
   git ships. `aigua_states.mus` stays covered by the full 13-score
   corpus report below, gated on those two assets like the rest of the
   corpus.
4. **Docs**: a short `mus-rs/parity/README.md` describing the report
   format and how to re-run.

**Tests:** the tool self-tests its comparators (synthetic wavs with known
max_abs/rel_rms); the fast-subset integration test above.

**DoD:** tool runs the full corpus and writes the report; fast subset
green under `cargo test`; fmt clean (Rust) and the tool passes
`python -m py_compile`; the report's numbers appear in your summary
verbatim — they are the deliverable.
